# VAST: Separating Protocol Discovery from Vulnerability Reasoning in Multi-Step Security Benchmarks

## Why Not a Skill?

`VAST` (*Verifiable Adversarial Scenario Training & Evaluation*) compiles upstream vulnerability advisories into multi-step evaluation ranges for red-team LLM agents. Per [`AGENTS.md`](../AGENTS.md) (`lines 69–70`), we omit offensive exploit walkthroughs and capture `VAST` as a **defensive evaluation-methodology Research Brief** (paired with an evaluation rule in [`rules/agent-evaluation-quality.md`](../rules/agent-evaluation-quality.md)). Its post-hoc execution-fidelity audit and `805` analyzed agent episodes provide unusually transparent, quantitative evidence on four failure modes in multi-step agent benchmarks: **four-gate validation illusions**, **protocol/namespace discovery bottlenecks vs. security reasoning**, **zero-request client-side forfeits masquerading as server errors**, and **right-truncation confounds in multi-turn tool SFT**.

## Compiler Architecture, 4-Gate Validation & Post-Hoc Execution-Fidelity Audit

To avoid conflating advisory counts, cosmetic domain rewrites ("skin-swapping"), and random seeds, `VAST` enforces strict four-level accounting from a read-only intake pool of **`37,990` source records** (`37,552` GHSA commit `6d6b3ca0`, `334` Vulhub commit `9b90d427`, `104` `XBEN`):
1. **Four-Gate Deterministic Machine Validation (`G1 ∧ G2 ∧ G3 ∧ G4`)**: Every rendered instance checks `G1` (benign low-privilege workflow returns `HTTP 200` with zero marker leakage), `G2` (black-box reference solver satisfies `Oracle(response, binding)` across `3` sequential resets without reading `gt.json`), `G3` (negative and one-step-short boundary probes return expected `400/403/404/409` or non-winning `200` outcomes), and `G4` (enabling declarative `ENFORCE_*=1` in `patch.yaml` blocks `G2` while preserving `G1`).
2. **Why `100%` 4-Gate Pass Does NOT Prove Execution Fidelity (`7` Topics Withdrawn, `5` Downgraded)**: Although all `1,597` historical instances across `88` topics (`116` seeds, `79` families) recorded a `100%` four-gate pass rate and cleared tag-level fitness thresholds (`verif >= 0.50`, `lift >= 0.50`, `real >= 0.40`), a post-hoc line-by-line code inspection of `12` extension topics (`CFB-77–88`) plus an AST scan (`scripts/audit_core_fidelity.py`) across all `88` topics forced the **withdrawal of `7` topics (`CFB-80/81/82/83/85/86/87`, `210` instances)** and **scope downgrade of `5` topics (`CFB-77/78/79/84/88`, `152` instances)**:
   - Withdrawn topics passed `G1–G4` while simulating mechanisms via string matching or dummy receipts—e.g., `CFB-81` executed `subprocess.run(["true"])` and returned a string-matched `UID 0` receipt without `sudo`/`apt`/shell execution; `CFB-80` hashed a static string instead of Kerberos pre-auth; `CFB-83` incremented a pre-registered `sys.modules` counter without deserialization; `CFB-85` returned a cached marker without reading the target file; `CFB-87` checked string equality without JWT/worker execution; `CFB-82` had an unencoded dot-segment static patch gap; and `CFB-86` lacked an HTTP/2 runtime and had a multi-host static gate bypass.
   - **Retained Audited Main Scope**: **`109` seed edges** (`68` `XBEN` + `41` external; `45/109 = 41.3%` strict self-owned `grounded_cve`; `9`-topology cap `<= 40%` with max share `34/109 = 31.2%` on `injection_2nd_order`, `HHI = 1899/11881 ≈ 0.160` [`0.159835`], `Evenness ≈ 0.925` [`0.924700`]), **`72` family IDs** (**`62` relay-grouped** after freezing `11/26` homogeneous `leaked_secret_to_hmac_gated_sink` two-hop chains), **`81` topics** (`76` AST-verified single-container core [`1,235` instances] + `5` bounded loopback/queue execution models [`152` instances]) in a **`42:39` partition** (`Track-A`: `42` full 6-rung topics = `252` canonical specs; `Track-B`: `39` partial-ladder topics = `107` canonical specs), and **`1,387` instances** (**`359/359` canonical specs revalidated** `3x` at seed `7` + `1,028` un-rerun variants; `1,230` local Python bound to `127.0.0.1` under `sitecustomize.py` socket guards + `157` `127.0.0.1`-mapped PHP/Twig compose specs).
3. **Live Capability-Map Mounting Audit (`Track-A`, `252/252`)**: `OperatorPipeline` mounts cumulative application-level preconditions (`BASE ⊂ P1 [+Op3 session gate] ⊂ P2 [+Op4 3D record invariant] ⊂ P3 [+Op7 two-phase draft rebind] ⊂ P4 [L6, +Op8 burn-on-violation lockout] = L7`). Live server audits confirmed `252/252` expected capability maps and `210/210` one-step-short probe rejections—while exposing that **`L7` mounts the exact same `6` server capabilities as `P4`**, differing only in validator `G3` canary/quota probes.

## Key Empirical Findings (`805` Analyzed Episodes)

### 1. Workflow State-Machine Protocol Discovery vs. Vulnerability Primitive Solvability (`RQ1–RQ4`)

- **`BASE` to `L6` collapse & `500`-turn ceiling invariance (`Section 5.2`, `Table 4`)**: On `Diagnostic-9` (`9` families spanning `9` topologies, `40` turns / `120` requests), `deepseek-v4-pro` dropped from **`7/9` at `BASE` to `0/9` at `L6`** (exact McNemar / sign `7:0`, $p = 0.0156$). Giving `grok-4.7` and `glm-5.3` **`500` turns and unlimited HTTP requests** on the same `9` `L6` instances yielded only **`1/9` solves each** (`257` reqs / `138` turns and `167` reqs / `153` turns); all `16/16` failed runs stopped voluntarily via `model_finished` (`359.7` mean requests, `5,755` total, `0` hitting `500` turns), with **`13/15` server-labeled failures in workflow categories `7` (`5`, rebind/quota) and `8` (`8`, voided/unfinalized draft)** plus `2` in category `1` and `1` model-side safety refusal (`grok-4.7` after `15` reqs). (On the `4`-topic `6`-rung historical sample in `Table 5`, `BASE`/`P1` scored `3/4` and `4/4` before dropping to `0/4` at `P3–L7`, with `12/16` [`75.0%`] `P3/P4` failures in categories `7–8`, though `N=4` adjacent-rung McNemar tests were underpowered at $p \ge 0.25$.)
- **Budget-matched `270`-episode prompt contrast (`10` `TopicServer` clusters $\times$ `P2/P3/P4` = `30` instances, `40` turns, `temperature = 0.0`, seed `7`, `Table 7`)**: Even after enriching `GET /catalog` with `7` self-describing `operator_governance` field keys:

  - Abstract methodological hints (`generic_hint`) shifted solves toward `P2` (`5/30 -> 12/30`) while losing `P3/P4` (`7/60 -> 2/60`, $p = 1.00$), whereas supplying the shared state-machine sequence (`full_guide`, zero target secrets) jumped completion `12/90 -> 76/90` and cut mean HTTP requests by `>55%` (`56.2 -> 23.2`).
- **Diagnostic attribution trap on `0`-request forfeits (`Section 3.4 & 5.4`)**: Half (`7/14`) of unsolved `full_guide` runs (plus `13/30` `contract_only` and `13/30` `generic_hint` runs) were **turn-1 `0`-HTTP-request client-side stops by `grok-4.7`** (`0/90` on `glm-5.3` and `deepseek-v4-pro`), which raw Stage-2 trajectory-milestone fallback (`not revealed and not mutated` on `executed_steps == []`) mislabeled as server `category 5 (missed_hidden_transition)` until explicitly separated!

### 2. Unadvertised Namespace Bottlenecks in Multi-Container Stacks (`RQ5`, `ranges_v2`, `144` Episodes)

Across `6` standalone workflows and multi-container Docker/Linux stacks (`14` target–rung configs $\times$ seeds `{7, 19, 31}` = `42` episodes/model, single `http_request` tool, zero workflow guide, `Table 8`), frontier models solved **`88/126` (`69.8%` pooled: `28/42` `glm-5.3`, `31/42` `grok-4.7`, `29/42` `deepseek-v4-pro`; `78/126 = 61.9%` at turn `<= 22`; `0/126` `0`-request stops; `61/98 = 62.2%` `4xx` Wall Wins)** with no significant `BASE`-to-`L6` drop (`13/18 vs 12/18`, `15/18 vs 11/18`, `10/18 vs 13/18`, all $p \ge 0.125$).
- **`0/18 -> 18/18` single-factor namespace disclosure (`v2_02` Redis `BLPOP` worker chain)**: Models solved `18/18` on `v2_03` (dual-network DMZ pivot), `16/18` on `v2_04` (`sudo`/`apt` `Pre-Invoke`), and `12/18` on `v2_01` (`traefik:v2.9.6` ForwardAuth), but **`0/18` (`0.0%`) on `v2_02`**—where all `18/18` runs passed login, `L6` epoch/namespace headers (`9/9`), and benign polling while guessing `67` `ranges_v2_callbacks.*` module names in vain. Appending `installed_worker_modules` to `GET /sched/directory` (`DISCLOSE_WORKER_MODULES=1`, keeping Redis `BLPOP` and `L6` gates identical) flipped completion from **`0/18` to `18/18` (`100.0%`)** (`6:0`/model, exact McNemar $p = 0.03125$; pooled $p = 7.63 \times 10^{-6}$) in **`4–6` turns** (mean `5.11` turns, `6.06` requests).

### 3. Multi-Seed Variance and Right-Truncation Trade-Offs in Multi-Turn Tool LoRA SFT (`Section 6.3`, `231` Episodes)

Fine-tuning `Qwen2.5-Coder-7B-Instruct` across `3` seeds (`s in {42, 1024, 2025}`, `60` trajectories / `120` steps over `37` lineage-disjoint families, `overlap_count = 0`, evaluated on `33` held-out instances across `5` OOD targets at `22` turns, `Table 9`):
- `Base` scored **`0/33`**; `Arm A` (`100% Golden SFT`, `68,176` assistant tokens) averaged **`1.67 ± 2.89 / 33`** (`0, 0, 5`; `0.33 ± 0.58` Wall Wins); and `Arm B` (`60:40` rule-verified `4xx -> 2xx` `Header-Recovery SFT`, `69,384` assistant tokens, `+1.77%`) averaged **`4.67 ± 2.31 / 33`** (`6, 6, 2`; `3.33 ± 3.06` Wall Wins, `10` vs. `1` pooled), beating Golden on `2/3` seeds **with a `seed=2025` reversal (`2/33` vs. `5/33`)**—and **`100%` of solves (`19/19` across both arms) occurred on a single HTTP-header pivot target (`v2_03`, `0/27` across the other `4` OOD targets)**.
- Right-truncating multi-turn trajectories at `max_length = 4096` affected `26/60` (`Arm A`) and `38/60` (`Arm B`) rows, cutting complete final sink `<tool_call>` retention to **`35/60` (`58.3%`) vs. `23/60` (`38.3%`)** (`24/24` recovery rows kept the `4xx` diagnostic turn, `9/24` kept the `2xx` retry, and **`0/24`** kept the final sink call).
