# Network-Exposed Configuration Planes in Embodied LLM Agents: Defensive Lessons

> **Source**: [arXiv:2611.22761](https://arxiv.org/abs/2611.22761) — Stanley Akingbola, Ugbede Ibrahim, Yan Lin Aung, Quang Dan Le, Hong Qing Yu (*Network-Exposed Configuration Attacks on LLM-Controlled Social Robots*, Nov 2026)

## Why Not a Skill?

Per [`AGENTS.md`](../AGENTS.md) defensive scoping guidelines, this paper is an empirical vulnerability assessment of a consumer LLM-controlled social robot (`Pollen Robotics Reachy Mini Lite`) paired with a `59`-repository GitHub audit of developer-to-consumer framework defaults (`Gradio`, `FastAPI`, `Streamlit`). Rather than introducing a new multi-step algorithmic skill, its engineering value lies in characterizing the **configuration-plane deployment gap**—showing that model-layer refusal cannot compensate for unauthenticated network-exposed management APIs (`CWE-306`, `CWE-1327`), `Content-Type`-agnostic `Request.json()` CSRF bypasses (`CWE-352`), or prompt-only persistent-memory restrictions—which translate directly into always-active control-plane and storage-sink guardrails in [`rules/agent-sandbox-safety.md`](../rules/agent-sandbox-safety.md) alongside [`Harden MCP servers, clients, and SDKs against shell interpolation, post-normalization path traversal, and local HTTP DNS rebinding`](../rules/agent-sandbox-safety.md). Offensive proof-of-concept payloads are omitted here in favor of strictly defensive architecture lessons.

## System Context & The "Deployment Gap" (`§1–§3`, `§5.1`)

Embodied social robots powered by cloud-hosted LLMs require continuous WiFi connectivity and frequently ship companion web configuration daemons (`Gradio`, `FastAPI`, `Streamlit`) on the host machine so operators can adjust robot personas, tools, and prompts from a browser:

- **Evaluated Architecture (`§3.1`)**: `Pollen Robotics Reachy Mini Lite` connected via USB 3.0 to a Windows 11 host running `reachy-mini-conversation-app` `v0.8.0` (`commit 81dfd7c`, using `Gradio v5.23.1`—past `CVE-2024-39236` in `v4.36.1`—and `FastAPI`/`uvicorn`) backed by a WebSocket session to the HuggingFace Realtime Speech cloud LLM.
- **Asymmetric Interface Binding (`CWE-1327`)**: While the co-resident `FastAPI` hardware daemon on `TCP 8000` bound strictly to `127.0.0.1`, launching the companion app with `--ui` explicitly bound the `Gradio` management interface to **`0.0.0.0:7860`**, exposing personality configuration routes (`personality_routes.py`) to every peer on the shared `/24` WiFi LAN (unless wireless AP client isolation is active) as well as co-resident local processes and browsers (`localhost:7860`).
- **Three-Phase Deployment Gap (`Table 6`)**: Prototyping frameworks optimize for frictionless local testing (`Gradio` and `FastAPI`/`uvicorn` default to `127.0.0.1` but expose the LAN via a single `--ui` / host flag; `Streamlit` binds a dual-stack wildcard address by default, and none of the three enforces authentication out of the box). When inherited unchanged into a consumer cyber-physical product, control-plane compromise alters the behavior of a physically co-located, socially trusted agent equipped with onboard cameras, microphones, speakers, and motors.

## Six Defensive Hardening Requirements (`§5.3`)

1. **Authenticate Every Control-Plane & Prompt-Management Route (`CWE-306`)**: Require a cryptographic session/bearer token (`HTTP 401` on missing/invalid credentials) at the route dependency layer *before* any handler reads or writes prompt files (`instructions.txt`), tool lists, or runtime sessions. A token issued once on local UI startup and sent via HTTP header adds negligible operator friction.
2. **Bind Companion UIs & Daemons to Loopback by Default (`CWE-1327`)**: Bind `Gradio`, `FastAPI`/`uvicorn`, and `Streamlit` management servers strictly to `127.0.0.1` by default (matching the co-resident `FastAPI` hardware daemon on port `8000`), requiring explicit authenticated operator opt-in (plus TLS/reverse-proxy termination) before binding `0.0.0.0` or dual-stack wildcards on shared WiFi networks.
3. **Eliminate `Content-Type`-Agnostic `Request.json()` CSRF Gadgets (`CWE-352`)**: Never assume that omitting permissive CORS headers prevents cross-origin state writes. Require state-changing endpoints to (a) carry credentials in a custom/authorization HTTP header (never ambient form submissions), (b) validate `Origin` / `Referer` against a strict trusted-origin allowlist in middleware (`HTTP 403` before route dispatch), and (c) enforce typed `application/json` schemas (e.g., Pydantic models) rather than raw `Request.json()` over `text/plain` CORS-safelisted simple requests.
4. **Verify Integrity & Surface Real-Time Operator Alerts on Instruction Changes**: Seal persisted personality/system-prompt files with an installation-time `HMAC` to detect out-of-band disk tampering, and log every configuration mutation with source IP alongside an immediate, operator-visible notification (and audible/visual cue on physical embodied hardware).
5. **Enforce Content & Sensitivity Policies Inside Storage Sinks, Not Tool Prose**: Never rely solely on `"do not save sensitive data"` instructions inside an LLM tool's natural-language description (`remember`). Enforce deterministic PII/secret scrubbing and lightweight sensitivity classification directly inside the underlying persistence function (`add_memory_fact()`) so neither conversational manipulation nor direct API invocation can commit credentials, addresses, payment data, or health records to persistent agent memory.
6. **Keep Downstream Output Guardrails Independent of Mutable System Prompts (`§5.1`)**: Because an attacker who rewrites the configuration-layer system prompt inherits any downstream guardrail that treats the active system prompt as trusted authority, anchor safety/actuation invariants in an immutable Ring-0 policy outside the editable personality configuration.
