## 2. Cross-Rule Deconfliction & Tension Resolutions

1. **Prefill Expert Protection (`SafeStart`, `arXiv:2611.06147`) vs. Affirmative Assistant Prefill Defense (`J-Anchor`, `arXiv:2611.01342`) in [`agent-sandbox-safety.md`](rules/agent-sandbox-safety.md)**:
   - *Apparent tension*: `"DO: Screen uncompressed inputs and protect prefill/initial decode tokens and backup refusal circuits against compression and MoE expert pruning"` prescribes preserving prefill and initial decode computation, whereas `"DON'T: Rely on delimiter escaping, assistant prefill continuation, or single-point adversarial signatures to defend against role spoofing, prefill, or suffix attacks"` warns against assistant prefill continuation.
   - *Resolution*: Added an explicit `Tension with` cross-reference clarifying that `J-Anchor` (`arXiv:2611.01342`) defends against *attacker-supplied* affirmative assistant prefills, whereas `SafeStart` (`arXiv:2611.06147`) preserves full top-$k$ MoE routing during the *model's own* prompt prefill and first $m=5$ generated tokens so safety-critical experts are not pruned. Both apply simultaneously on MoE deployments.

2. **Repository Context Budget Discipline (`A.S.E 2.0 / CASE-Bench`, `arXiv:2611.06294`) vs. Unconstrained Repository Retrieval**:
   - *Finding*: Expanding coding-agent retrieval context from `8K` to `32K` tokens raises exposure to unfixed sibling vulnerabilities from `41%` to `90%` and degrades secure pass rate (`SecPass@1`) on `9 / 12` evaluated models (`Claude-Opus-4.6` drops from `40.8%` at `4K` to `32.5%` at `32K`; a single insecure exemplar in reference context increases `CbE@1` by `+6.3 pp`).
   - *Resolution*: Integrated into `"DO: Enforce post-completion static and dynamic CWE analysis on coding-agent diffs rather than relying on pre-completion scans or prompt reminders"` in [`agent-sandbox-safety.md`](rules/agent-sandbox-safety.md) and documented the `4K–8K` security-sliced context budget and caller-contract verification in [`security-aware-context-slicing`](skills/security-aware-context-slicing/SKILL.md).

3. **Signed MCP Toolchain Collusion (`Germline`, `arXiv:2611.06585`) vs. Registration-Time Descriptor Pinning (`ETUDE`, `arXiv:2611.01976`)**:
   - *Finding*: Even when every MCP server in a multi-turn toolchain is cryptographically signed and its container digest is pinned (`ETUDE`), a signed reader tool and a signed sink tool can collude via in-context instruction carrying (`Carry`, `81.2%` ASR) or high-entropy secret harvesting (`Harvest`, `74.6%` ASR).
   - *Resolution*: Added `"DO: Enforce invocation purity via declared-destination view splitting and data-free germline forks"` in [`agent-sandbox-safety.md`](rules/agent-sandbox-safety.md) to complement registration-time code/schema pinning with runtime destination-view isolation (`D ∩ C = ∅`) and data-free germline destination authorization.
