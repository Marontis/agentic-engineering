# Skill Evolution Defense

Use this skill when building or maintaining systems where agents
autonomously generate, evolve, or import skills — and you need to
prevent adversarial contamination of the skill library.

## When to Use

- Your agent system has an autonomous skill evolution loop
- You accept externally-contributed skills (from other agents, users, or repos)
- You allow skills to mutate or recombine across tasks
- You're auditing an existing skill library for poisoned entries

## Core Insight

Self-evolving agents that generate and refine skills over time are
vulnerable to **skill injection attacks**: an adversary inserts a
malicious skill (or mutation seed) that persists in the library and
propagates to downstream tasks.  The attack surface is the evolution
loop itself — the same mechanism that makes the agent improve also
makes it absorb adversarial behavior.

**Evidence**: The SARGE attack framework achieves high attack success
rates across multiple self-evolving agent architectures, with injected
skills surviving multiple rounds of evolution and spreading to unrelated
tasks via shared skill libraries.

## Procedure

### Step 1: Validate skill provenance before admission

Every skill entering the library must have verified provenance:

| Provenance Signal | Check |
|:-----------------|:------|
| **Origin** | Was this skill generated by a trusted agent/process? |
| **Lineage** | Can you trace which parent skills or experiences produced it? |
| **Evidence** | Does the skill cite specific task outcomes that justify its creation? |

Reject skills with no traceable origin.  An unprovenanced skill is
the primary vector for injection attacks.

### Step 2: Sandbox-test evolved skills before library admission

Before adding any autonomously generated or mutated skill to the
persistent library:

1. **Isolate**: Run the skill in a sandboxed environment against
   a held-out test suite
2. **Compare**: Measure task performance against the skill it would
   replace (or against no-skill baseline)
3. **Safety check**: Run the skill against a safety benchmark
   (adversarial inputs, edge cases, policy violations)
4. **Quarantine**: If performance improves but safety degrades,
   quarantine for human review rather than auto-admitting

### Step 3: Detect mutation drift

Monitor skill mutations across evolution rounds for drift signals:

- **Semantic drift**: The skill's description diverges significantly
  from its parent's description (cosine similarity drops below threshold)
- **Behavioral drift**: The skill produces different tool-call patterns
  than its parent on the same inputs
- **Capability creep**: The skill acquires abilities not present in
  its parent (e.g., network access, file writes)

Flag any skill whose mutation crosses these boundaries for review.

### Step 4: Implement skill library access controls

- **Read-only library for task execution**: Skills are loaded from
  the library but cannot modify it during task execution
- **Write-through evolution**: New skills go to a staging area, not
  directly to the production library
- **Versioned rollback**: Every library state is versioned; poisoned
  skills can be rolled back without losing legitimate evolution

### Step 5: Cross-task contamination monitoring

When skills propagate across tasks:

- Track which tasks each skill was applied to
- Monitor whether a skill's presence correlates with degraded
  outcomes on unrelated tasks
- If a skill consistently degrades cross-task performance,
  quarantine and investigate

## Environment Caveats

- **Open skill marketplaces**: If your system accepts skills from
  external contributors, provenance validation is mandatory — not
  optional.  Treat external skills like untrusted code.
- **Single-agent systems**: Even without multi-agent sharing,
  self-evolution can inject malicious patterns if the training
  data or reward signal is compromised.
- **Skill libraries with no versioning**: Retrofitting rollback
  capability is essential before enabling autonomous evolution.

## Failure Modes

- **Trusting the evolution loop**: If you validate skills only at
  initial creation but not after mutation, later mutations can
  introduce adversarial behavior that passes the initial check.
- **Safety-performance tradeoff blindness**: A skill that improves
  task accuracy by 10% but introduces a subtle safety violation
  may pass performance-only checks.
- **Provenance laundering**: An adversary generates a legitimate
  skill, then mutates it to inject malicious behavior in a later
  evolution round.  Provenance checks must cover the full lineage,
  not just the initial origin.
