# Test Before Extending

When iterating on an application—especially when extending code that was recently generated by an agent—you **must** verify the existing baseline works before adding new features.

This addresses the "vibe-on-vibe" (or "slop-on-slop") failure mode identified in Replit's ByteBench evaluations, where models severely underperform when trying to extend unverified agent-generated code.

## Rules

1. Before starting a new feature or structural change, run the test suite or manually verify the component you are modifying.
2. If tests fail, fix the baseline **first** before proceeding with the feature request.
3. Do not assume agent-generated code from a previous turn is structurally sound without verification.
